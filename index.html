01 / Python · Appium · iOS

A repeatable way to test native iOS apps.

UI tests become difficult to maintain when every test knows every screen. This framework separates screen interactions from test intent.

The problem
Native iOS checks across Settings, Calendar, Messages, and Maps need reusable steps and clear results.
What I built
A Python and Appium framework using page objects to separate screen interactions from test intent.
The result
Device-free tests run in CI. Opt-in simulator checks clean up app state and save screenshots, page XML, and logs on failure.

02 / Python · Lab automation · Internal tool

Less setup. More time to test.

Device restoration was repetitive preparation work. I built a Python tool to streamline that workflow for the engineering team.

40% less manual test setup time across 30+ devices

Reported result from the internal test environment automation project. Source code is not public.

Inside the workflow

Compare lab preparation workflows

Repeat the setup for each device.

  1. Identify the device and target configuration.
  2. Start restoration manually.
  3. Check the result before the next device.
  4. Repeat preparation across the test rack.

Let a repeatable script handle restoration.

  1. Select the devices and intended configuration.
  2. Run the restoration workflow.
  3. Review results and investigate exceptions.

Illustrative workflow; simplified to explain the approach.
